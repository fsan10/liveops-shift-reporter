# 运维说明

## Cloak Login 测试模式

1. 后台按 profile 名称或可选 ID 调用本机 Cloak MCP `list_active`；若目标未运行，调用 `start_profile`。每次均使用实时返回的 CDP 地址。
2. 采集前复用抖店标签打开首页，登录态失效时调用复用的抖店邮箱登录/店铺选择状态机。可见滑块由人工处理，后台向配置的飞书负责人发送 @ 提醒并等待，不读取或绕过验证码。
3. 罗盘直播列表的实时接口返回本次 `live_room_id`。当天排班按此 ID 生成详情、专业版、基础版和千川最短直达 URL。详情页每次重新加载后截取成交转化漏斗；专业版、基础版和千川大屏复用匹配直播间的标签，不重新加载页面。新直播间或路由不匹配时才导航，直达失败才执行配置的 DOM 路径。
4. 千川顶部指标卡必须选中“全域支付数据”；接口必须返回同口径的消耗、券、补贴、曝光、GPM 和顶部成交/ROI 卡片，截图前核对 7 个卡片数值与该响应一致。已结束的直播可能停止自动轮询，专业版/基础版通过浏览器内原页面 GET 接口补取数据，由页面 SDK 生成新签名；千川重新选择指标卡口径触发原生接口更新，不重载大屏。接口未就绪自动重试一次；超过等待上限保留具体中文缺失原因，不把空响应或 `--` 当作完成。
5. 截图模式保持成交转化漏斗为元素截图，其余模块为整页截图。罗盘截图前检查页面视口；小于 1280×720 时，临时扩展到可用屏幕尺寸（最大 1920×1080）后截图，并恢复原视口，不改动 Cloak 窗口大小。千川保留现有整页截图路径。

## Playwright 原生浏览器生产模式

切换到“原生浏览器”后，后台在 `NATIVE_USER_DATA_DIR` 创建持久化 Chromium profile。首次启动需人工登录平台并确认账户、店铺与广告账户；后续任务复用该 profile。`locale`、`timezone_id`、视口、缩放倍率和浏览器路径可在配置页修改。浏览器实际支持的指纹范围取决于 Playwright/Chromium；Cloak 专属的 Canvas、WebGL 或字体伪装不会自动迁移。

## 飞书配置

使用企业自建应用机器人模式，不是仅有 webhook 的自定义机器人。填写 App ID、App Secret、目标群 Chat ID，以及多维表格 app_token、table_id。机器人必须启用并加入群聊；应用需获准发送消息，并开通 `im:resource:upload` 或 `im:resource` 应用身份权限以上传图片；对目标多维表格还需有查看、编辑权限。报告按“直播数据报告：”标题、图片、说明文字的顺序发送。系统先上传截图获得 `image_key`，再发送图文消息，所以仅验证文本测试消息不能证明截图链路可用。多维表格字段名通过字段映射与表格中的实际列名对应。

新建排班只需填写日期、主播和开始/结束时间。当天排班的直播间 ID 会从罗盘实时列表自动发现；千川账户 ID 沿用系统配置的默认账户，不需要在每个排班重复填写。人工采集只允许当天排班，历史和未来排班会在任务入队前被拒绝；定时任务仍按排班结束时间运行。

排班管理复用 2026 年 10 月原型的日期卡片、月历、人员弹层、时段模板、休息/拍摄编辑、侧栏统计和撤销操作。原型中的“运营”在项目中统一作为“投手”，与主播一起保存在班次中。新增班次先出现空行，补全时段和主播后自动写入服务端；未补全的空行保存在当前浏览器。操作列提供开始采集、标记中断、停用/启用、删除，列表中的班次修改直接点击对应单元格；月历点击班次或新增空班次后打开“时段、主播、投手”菜单，悬浮或点击选项展开二级设置。时段支持开始/结束时间输入与常用模板，主播和投手支持候选选择、搜索或输入姓名；设置后自动保存，按 Escape 或点击外部关闭菜单。自动排班按目标日期的星期轮换 2026 年 10 月模板，并复制休息和拍摄备注；已有内容时不会覆盖。点击“恢复原始”仅恢复当前月份今天及未来日期的模板排班；待替换日期存在采集报告或记录时拒绝替换，以保留审计记录。原“从罗盘导入轮班”入口和接口已移除。

排班日期按 `Asia/Shanghai` 判断。今天之前的日期只读，不能新增、编辑、启停或删除班次，也不能修改休息/拍摄备注；后端接口同步拒绝这些操作。列表将历史日期默认折叠到“历史排班”，展开后覆盖半透明灰色蒙版并禁止交互，保留原有人员颜色；月历完整显示历史日期并使用同样的蒙版。今天的整个日期区域有浅蓝细框及向外扩散的柔光。首次打开、重新进入排班管理或切换列表/月历时回到本月并自动将今天显示在固定工具栏下方；浏览其他月份可继续使用月份按钮。自动排班及恢复模板跳过历史日期，保留历史班次和备注。页面加载时清除 2026 年 10 月 1 日误加、未保存且时段/主播/投手均为空的本地班次；已保存班次和其他草稿保留。历史草稿不会自动写入后端，也不会导致列表渲染失败。修改程序后由操作员重启后台以使后端日期限制生效；刷新页面可加载新的前端。

公开 GitHub 提交应排除真实人员名单、实际班表、数据库和浏览器缓存，但必须保留通用调色板、自动分色逻辑和配色回归测试；脱敏只清理拟提交的代码及示例，不清空本机业务数据。人员配色使用通用的多色调色板，与真实姓名配置分离；已分配颜色缓存在当前浏览器，列表、月历、侧栏和人员菜单保持一致，刷新、切换月份或调整名单不重新分配。没有缓存的新人员自动补色，颜色缓存损坏或浏览器禁用存储时仍可正常显示。侧栏“主播班次统计”和“投手班次统计”的设置按钮管理可选人员。公开安装的默认人员名单为空，需要在系统配置中添加当前团队成员。名单分别保存在系统配置 `roster_anchor_pool` 与 `roster_promoter_pool`，删除人员仅移出可选名单，不改已有班次。排班视图只使用内部滚动条，日期工具栏和视图切换栏固定在顶部；排班连接及保存状态与服务状态在主界面顶部胶囊轮播显示。若旧服务尚未重启，新名单暂存当前浏览器，重启后自动同步到配置。

## 运行和恢复

- 罗盘可能短暂显示未登录，随后通过抖店登录态完成自动跳转。抖店登录正常不等于罗盘接口已经就绪。场次发现收到响应时立即读取正文，页面导航后丢弃旧文档响应；只有同一文档的实时和历史列表接口均有效、罗盘路由稳定后才继续。每次等待上限沿用 `PORTAL_TIMEOUT_MS`（默认 45 秒），超时只重新打开一次直播列表，不重启 profile、不改变账号或绑定场次。失败时保留标签，人工检查登录、验证及权限后再采集。
- 手动/定时任务彻底失败、字段或页面缺失、群报告发送或多维表格同步失败时，机器人向已配置的群发送“直播运营异常提醒”，包含北京时间、排班/主播、失败环节、原因判断、处理建议和运行编号；沿用 `feishu_alert_open_id` 可 @ 负责人。原因判断是根据错误类别生成的提示，详细原始错误仍在后台。只因班次未结束产生的临时快照不提醒。同一运行只尝试一次终态提醒，重试采集是新的运行；滑块等待期间的人工接手提醒仍单独保留。
- 运行详情的 `exception_alert` 和“异常提醒”步骤保存发送状态及成功消息 ID；未配置或发送失败也留痕，原始采集错误不被覆盖。飞书业务返回成功且存在消息 ID 才标记送达。网络超时可能无法确认消息是否到群，因此不自动重发提醒；机器人或网络不可用时只能在后台看到提醒失败。先检查飞书配置/权限/网络。已经保存的数据可按后台实际结果重试同步，避免重复发送成功的群报告。修改程序后需要操作员重启后台，新异常提醒才会用于后续任务。
- 采集记录页记录每次手动或定时触发，展示开始与完成时间、逐步运行日志、缺失指标和错误摘要。数据明细与采集记录分页默认每页 20 条，页数可单独记忆。
- 首次采集发现并绑定直播场次，之后优先使用排班已绑定的 ID，其次使用上一班最终快照的 ID；正常停播或跨午夜不会解除绑定，也不会因另一个场次在线而自动切换。场次身份在详情接口确认后独立保存，其他指标缺失不会丢失场次。`live_author_id` 可固定账号；多账号歧义或接口失败停止归属。
- 正常班次按实际快照交接：第一位基线为零，后续同场累计值减上一位最终快照。导航、等待结算及截图引起的正常延迟仅记录实际时间，不因晚于排班结束几十秒而 partial。真实接口缺失、无上一位基线、账户不匹配或累计回退仍需处理。
- 断播续播时，在该排班行点击“标记中断”，选择中断时间并点击“标记并采集”。立即保存绑定的旧场片段，成功保存后才允许发现新场；不提前替换完整报告或向下一班传基线。班次结束时，新场从零开始，与旧场增量合并；下一位只继承新场结束快照。多次断播需分别标记，同场重试替换原片段且不改绑已确认的新场。重新发现按实际班次日期范围查询全部历史分页，包括跨天的前一天；多个未保存场次必须分别标记，不能自动跳到最新场。没有续播时只结算已保存旧场片段。普通下班停播无需标记中断。
- 成交人数、点击人数、场观、增粉为同场累计净增量；跨场相加不做联合去重。GPM、互动率、停留使用最后一场结束时的页面卡片，各场原值见详情。这些卡片不是跨场平均指标。当天最后一个排班时段完成后，日曝光按直播间 ID 去重，取当天每场最新的直播间整体曝光并求和，然后回填当天所有已生成时段并同步多维表格；同一直播间跨多个时段只计一次，手动标记断播后的不同直播间分别计入。缺少任一场的有效最终快照时整日留空并注明原因，不用时段曝光差分代替。完整口径见 data-sources.md。
- `shift_interruptions` 持久保存中断时间、room、广告账户、快照、原始响应和截图；程序重启后继续合并。完整报告按同一排班更新，不重复累加；临时报告在结束时重新结算且不能作下一班基线。
- 截图后保留详情、专业版、基础版、千川和直播列表标签页，包括页面失败时。下一次复用同场标签，详情页刷新，实时大屏等待新的有效接口与已渲染卡片，不重载匹配大屏。只移除本次响应监听器。
- 千川旧标签在停播后可能保留卡片但不能产生新响应。切换全域支付并重试仍超时时，保留原标签，额外初始化一次相同直播间和广告账户的页面；取得新接口且卡片数值一致才继续截图。下一次优先复用这个较新的同场标签，不自动关闭旧页。
- 修改程序后由操作员重启后台，启动会创建中断记录表并保留原排班/报告。已存在的旧自动分段报告保留旧口径；本次不会用晚到的最新整场累计值覆盖历史班次。
