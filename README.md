# 直播运营数据采集与报表

本项目面向抖音电商罗盘与巨量千川直播大屏，按主播排班采集直播数据，生成截图，保存本地报表，并可同步至飞书群聊和飞书多维表格。

## 已实现范围

- Windows + Python 虚拟环境运行的 FastAPI 后台，内置 SQLite。
- 按原型列表与月历维护排班、自动排班、按主播采集顺序自动接续基线、结束时刻采集、人工立即执行、启用/停用、独立采集记录页和截图查看。
- 五个截图模块：详情页成交转化漏斗元素截图；专业版流量分析整页截图；专业版主播分析整页截图；基础版整页截图；千川大屏整页截图。
- 通过 Playwright 监听页面调用的 JSON 接口，读取轮班、漏斗、直播交易/流量、千川投放数据；不以页面文字识别作为主数据源。
- 表格计算、按日期查看数据、浏览器指纹基础参数、飞书应用机器人和多维表格配置页。
- 飞书应用凭证加密落库；未配置凭证时，采集和本地报表仍可单独运行。
- 罗盘登录过渡期间等待有效接口并限次重试；采集、页面/字段及同步异常由机器人在群内提醒，记录发送结果和人工处理建议。
- 自动调度提供“获取数据”“每小时截图”“主播时段截图”三个独立开关。主播汇总与基线按排班结束点采集；小时任务按排班分段，采集独立小时指标、基线和截图并发业务群。两类截图在同场同账户的同一计划时点重合时共用一套图片，分别发各自的群。

## 本机运行

PowerShell：

```powershell
Copy-Item .env.example .env
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
```

修改日期、时间范围或分页组件时，在项目根目录运行 `npm ci` 和 `npm run build:widgets`，将生成的 `liveops/static/widgets.bundle.js` 一同发布。日常启动不需要运行 Node 服务。

测试环境由后台通过本机 Cloak MCP 自动查找或启动指定 profile，并获取本次运行的 CDP 地址，无需业务人员填写。生产环境可切换 Playwright 原生 Chromium；浏览器由程序自行启动，不使用 CDP 地址。原生浏览器首次使用需完成账号登录，后续复用持久化数据目录。

```powershell
.\.venv\Scripts\python.exe -m playwright install chromium
.\.venv\Scripts\uvicorn.exe liveops.app:app --host 127.0.0.1 --port 8765
```

打开 <http://127.0.0.1:8765>。第一次启动时会在 `var/master.key` 生成本地 Fernet 密钥，并创建默认采集模块。运行服务的账号需要能访问浏览器、互联网、飞书开放平台，并有 `var/` 写入权限。

## 第一次配置

1. 在“配置 → 浏览器”选择 Cloak 模式并确认目标 profile 名称；或选原生 Chromium 并完成登录。
2. 设置千川广告账户 ID、店铺名。首次采集自动发现并绑定场次；之后沿用排班或上一班的场次 ID，已停播也可直接采集该场。多直播账号时填写 author_id。人工采集仅允许当天排班，中断在排班行手动标记。
3. 在排班管理的日期卡片或月历中添加班次，直接点击时段、主播、投手以及休息和拍摄选项修改；每个日期的主播名必须唯一，时间段不可重叠。空班次会留在当前浏览器，补全时段与主播后自动保存到服务端。右侧统计栏的设置按钮可维护主播和投手可选名单；移出名单不会修改历史班次。自动排班使用 `liveops/data/schedule_template_2026-10.json`；公开示例文件里的主播、投手和时段均为虚构内容。真实使用前请复制 `schedule_template_2026-10.example.json` 为本机模板并替换为实际排班，本机模板已由 `.gitignore` 排除。
   也可点击工具栏“导入 Excel”，下载模板填写后预览并确认导入。支持 `.xlsx` 和原导出 `.csv`；历史日期和重复班次跳过，格式错误或冲突阻止整批导入，不覆盖已有排班。字段格式及接口见 [Excel 排班导入](docs/operations.md#excel-排班导入)。
4. 在“脚本管理”启用所需页面，再运行一次人工采集检查截图和字段。
5. 在“配置 → 飞书”填写企业自建应用 App ID、App Secret、主播群 Chat ID、业务每小时群 Chat ID、登录/滑块负责人 Open ID、表格 app_token/table_id 和字段映射。两个群可共用应用凭证，机器人须加入对应群；业务群留空不会转发到主播群。两种截图文案和测试按钮独立配置。负责人 Open ID 同时用于异常提醒的 @。应用需要机器人消息与多维表格读写权限。
6. 启用排班。第一位基线为零，后续同场累计快照减上一位最终快照。正常采集耗时不判为部分完成。断播时点击“标记中断”采集旧场，班次结束合并新场，新场从零开始；下一位只继承新场结束快照。截图标签保留供下次复用；按功能开关发送截图、保存数据并同步已配置的多维表格。口径详见 docs/data-sources.md。
7. 在“配置 → 自动调度”设置三个开关并保存。若主播自己截图、数据仍需采集、业务每小时看图，设置为：获取数据开、每小时截图开、主播时段截图关。升级默认保留旧行为（数据开、主播截图开、小时截图关），旧群配置继续作为主播群使用。

## 运行边界

- 定时器以 `Asia/Shanghai` 为准，每 15 秒检查一次到期任务；结束采集默认延迟 30 秒，减少数据落后造成的误差。
- 小时任务依附主播排班：每次剩余不少于 2 小时就划出 1 小时，不足 2 小时合并为末段。07:00–11:30 分为 07–08、08–09、09–10、10–11:30；跨午夜保留父排班业务日期。小时累计基线与主播汇总基线分开，末段共用一次采集和截图。数据明细页点击主播行可展开小时明细，飞书以汇总父记录和小时子记录同步。后台需要持续运行。
- 日期、时间范围和分页使用本地打包的 Ant Design 组件。数据明细和采集记录页默认每页 20 条；两页分别记住浏览器本地选择的分页大小。SQLite 保留全部报表，多维表格只同步当月数据并在跨月后清理已同步的上月记录。
- Cloak 模式复用已有标签。每次漏斗截图重新加载详情页；专业版、基础版和千川大屏保持页面，通过页面接口补取最新数据。千川明确选择“全域支付数据”，必要指标接口和卡片加载完成后才截图，超时自动重试一次并记录具体缺失指标。只在直达 URL 失败时尝试页面点击兜底。不会关闭或重启已运行的 profile；单个浏览器 profile 同一时刻只跑一个任务。
- 页面接口属于平台前端接口。代码保留接口路径与指标映射版本；若平台变更字段、页面鉴权或风控流程，运行记录会提示缺少数据，不会把缺失值伪装为 0。
- 浏览器截图和本地数据库保存在 `var/`，不会进入 Git。不要将真实飞书密钥、CDP 地址或含商家数据的截图提交到仓库。

## 断播、续播与跨场次班次

首次采集按直播账号发现并绑定场次，之后持续使用排班或上一班交接快照的直播间 ID。午夜之后不依赖在线列表，正常停播也继续打开已绑定场次收尾。只有手动保存中断后才寻找未保存的新场，已绑定的新场再次采集仍沿用其 ID。需要发现时按实际班次日期范围查询完整历史，包括跨天班次的两个日期；多场歧义不会直接选择最新场。多账号时在系统配置填写“直播账号 ID（author_id）”；支持环境变量 `DEFAULT_LIVE_AUTHOR_ID`。

详情页展示每个场次、归属区间、实际已播时长和缺失口径。GMV 为区间用户支付金额；跨场去重人数、相关比率与缺少同场基线的千川指标会留空。班次结束前的快照由调度在结束后重新结算。代码更新后需由操作员重启现有后台，重采目标班次更新原记录；测试不会重启已运行的服务。
